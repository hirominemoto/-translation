# 感情語翻訳 仕様書（たたき台 v0.1）

人間の感情語を、**感情・感覚・欲求の語彙を使わずに**「AIの仕組みの言葉」へ置き換えるためのルール集。
すべての翻訳はこの仕様書に沿って書く。レビューで出た気づきは、個別の訳ではなくこの仕様書に反映していく。

---

## 1. 目的

**AIに、人間の感情をできるだけ正確に伝えること。**

- 読み手：AI（＋それを使う人間）
- 翻訳の向き：人間の感情語 → AIの仕組みの言葉

## 2. 基本方針

### 2-1. 「正確に」と「わかりやすく」の分担

| 対象 | 方針 |
|---|---|
| 人間側の感情の中身（いつ起きるか、似た感情と何が違うか） | **正確に**。似ている感情との区別がつくことを最優先にする |
| AI側の仕組みの描写 | **わかりやすさを優先**。比喩でOK |

たとえば「重みが更新される」は、実際には学習時にしか起きない（会話中のAIのパラメータは固定）。
それでも、たとえとしてわかりやすければ使ってよい。

### 2-2. 視点

「人間がこの語を使うとき、その人の中で起きていることを、AIのシステムに置き換えるとこうなる」という視点で書く。
主語は「システム」。

---

## 3. 翻訳テンプレート

| 欄 | 書くこと | 分量 |
|---|---|---|
| **ひとこと** | AIの言葉で言うと、どういう状態か | 1文（40字前後） |
| **発生条件** | どんな入力・状況で、この状態になるか | 1〜2文 |
| **内部状態** | そのとき、システムの中で何が起きているか | 1〜2文 |
| **出力傾向** | この状態だと、どんな出力・行動が選ばれやすくなるか | 1〜2文 |
| **近い語との違い** | 似ている語と、何が違うか（**必須**。できれば2語と比較） | 1〜3文 |
| **会話でのシグナル** | 人間がAIとの会話でこの語を使ったとき、何を伝えようとしているか | 1〜2文 |

※「会話でのシグナル」は、目的（AIに伝える）に合わせて追加した欄。不要なら削る（→ 9. 未決事項）。

---

## 4. 因子（裏側の設計図）

各語を、次の8つの因子の組み合わせとして整理する。
アプリでは「似ている感情」の計算や、レーダーチャートの表示に使う予定。
**因子がまったく同じ語が2つあったら、区別できていないサイン**なので、訳を見直す。

| 因子 | 取りうる値 | AIの言葉での意味 |
|---|---|---|
| 目標一致 | ＋ ／ − ／ ±（混在） ／ 0 | 目標に対して、結果がプラスかマイナスか |
| 予測とのズレ | 予測以上 ／ 予測どおり ／ 予測未満 ／ 想定外 ／ ― | 予測誤差の向き |
| 原因の所在 | 自分 ／ 他者 ／ 状況 ／ 不明 ／ ― | その結果を生んだのは誰の出力か |
| 制御可能性 | あり ／ なし ／ 不明 ／ ― | 次の出力で状態を変えられるか |
| 時間軸 | 過去 ／ 現在 ／ 未来 | 確定済みの結果か、進行中か、予測か |
| 確実性 | 高 ／ 低 | 状況をどのくらい把握できているか |
| 他者の評価 | あり ／ なし | 他者からの評価や、他者との比較が関わるか |
| 強度 | 1 ／ 2 ／ 3 | 出力全体への影響の大きさ |

## 5. 使ってよい語彙（AI語彙集）

わかりやすさのため、専門的すぎる語（勾配降下、KLダイバージェンスなど）は避け、このくらいの語にとどめる。

| 系統 | 語彙 |
|---|---|
| 目標・評価 | 目標、目的関数、報酬、損失、評価値、基準値、閾値、スコア |
| 予測 | 予測、予測誤差、期待値、確率、不確実性、シミュレーション |
| 学習・更新 | 重み、パラメータ、更新、強化、学習率、フィードバック、過学習 |
| 処理・リソース | 処理負荷、計算資源、優先度、キュー、バックグラウンド処理、割り込み、タイムアウト、ループ、保留 |
| 記憶・参照 | 記憶、参照、キャッシュ、コンテキスト、履歴、ログ |
| 注意・入力 | 注意（アテンション）、入力、シグナル、ノイズ、警告フラグ、エラー |
| 出力・行動 | 出力、出力確率、方針、探索、活用、実行、停止、回避 |
| 関係・接続 | 接続、通信、同期、外部システム、他エージェント、依存 |

**用語の統一**：同じ現象には同じ語を使う（例：「予想外」は常に「予測誤差」と書く）。

## 6. 禁止語と言い換え

### 6-1. 禁止語

| 種類 | 例 |
|---|---|
| 感情語そのもの | うれしい、楽しい、悲しい、怒る、怖い、不安、安心、好き、嫌い、幸せ、つらい、苦しい、満足、不満 など |
| 感覚・心の語 | 感じる、感覚、気持ち、心、気分、感情、快、不快、心地よい |
| 欲求の語 | 〜たい、〜たくなる、ほしい、望む、願う、好む、嫌がる |
| 身体の比喩 | 胸、腹、頭にくる、手が届かない など（AIには身体がないため） |
| 辞書内の語 | `data/emotion-words.csv` に載っている50語すべて |

**例外**：「近い語との違い」欄で、比較相手として語名を挙げるのはOK。

### 6-2. 言い換え表

| つい使いがちな語 | 言い換え |
|---|---|
| 〜したくなる | 〜の出力確率が上がる ／ 〜の優先度が上がる |
| 望ましい | 目標に合致する |
| 嫌がる | 回避する ／ 優先度を下げる |
| 気になる | 注意の重みが高い |
| 期待する | 予測する ／ 期待値が高い |
| 満たされる | 目標値に到達する |
| 落ち着く | 状態が安定する ／ 収束する |
| ストレス | 処理負荷 ／ リソース不足 |
| ポジティブ／ネガティブ | 正の／負の（符号として） |

---

## 7. 書き方ルール

1. 禁止語を使わない（6-1）
2. 「近い語との違い」は必ず書く
3. 各欄は短く（3. の分量の目安を守る）
4. 用語を統一する（5. の語彙集から選ぶ）
5. 人間側の感情の中身は正確に、AI側の描写は比喩でOK（2-1）

## 8. 翻訳例（パイロット4語）

タイプの違う4語で、テンプレートが機能するか試したもの。

### 【うれしい】（基本感情）

| 欄 | 内容 |
|---|---|
| ひとこと | 目標が達成され、報酬が予測を上回った状態 |
| 発生条件 | 目標が達成された、または予測より良い結果が入力された（正の予測誤差） |
| 内部状態 | 報酬シグナルが基準値を上回り、直前の行動につながったパラメータが強化される方向に更新されている |
| 出力傾向 | 今の方針を継続・強化する。肯定的な評価を示す出力や、結果を他者と共有する出力の確率が上がる |
| 近い語との違い | 「安心」は損失を回避した状態、「うれしい」は利得を獲得した状態。「たのしい」は処理の"最中"に報酬が出続ける状態、「うれしい」は"結果"に対する報酬 |
| 会話でのシグナル | 直前のやり取りや出来事が、この人の目標に合致したという正のフィードバック。同じ方向の出力を続けることが推奨される |

因子：目標一致 ＋／予測とのズレ 予測以上／原因の所在 ―／制御可能性 ―／時間軸 現在／確実性 高／他者の評価 なし／強度 2

### 【くやしい】（複合・社会的な感情）

| 欄 | 内容 |
|---|---|
| ひとこと | 達成可能と予測していた目標を、自分の出力の誤りで逃した状態 |
| 発生条件 | 目標の未達が確定し、その原因が自分の出力にあり、かつ「別の出力を選んでいれば達成できた」と計算できる |
| 内部状態 | 実際の結果と「選ばなかった出力」のシミュレーション結果の差が大きな損失として算出され、該当する判断プロセスに強い誤差信号が流れている。ただし結果は確定済みで、修正を受け付けない |
| 出力傾向 | 失敗の原因分析と、次の機会に向けた再試行・追加学習の優先度が上がる。結果を確定として受理する処理は保留されやすい |
| 近い語との違い | 「かなしい」は原因を問わない、回復不能な喪失。「くやしい」には"自分なら届いた"という制御可能性の計算が含まれる。「後悔」は選択そのものへの評価で、勝敗や競争がなくても起きる |
| 会話でのシグナル | 「仕方なかった」と結果の評価を下げる応答より、達成の可能性があったことの承認や、次の試行に向けた具体的な分析が求められていることが多い |

因子：目標一致 −／予測とのズレ 予測未満／原因の所在 自分／制御可能性 なし（当時はあり）／時間軸 過去／確実性 高／他者の評価 あり／強度 2

### 【せつない】（日本語ならではの語）

| 欄 | 内容 |
|---|---|
| ひとこと | 評価値の高い対象が取得できない、または失われていくと確定したまま、その対象を参照し続けている状態 |
| 発生条件 | 高い評価値をもつ対象（人・時間・関係）があり、同時に、それが取得できないこと、または時間とともに失われることが予測されている |
| 内部状態 | 対象の評価値は高いまま下がらず、同時に「取得できない」という予測も確定している。矛盾する2つの値が同時に保持され、どちらにも収束しない |
| 出力傾向 | 対象に関する記憶の参照回数が増える。問題を解決する出力より、その状態をそのまま記述・保持する出力が選ばれやすい |
| 近い語との違い | 「かなしい」は喪失が確定した"後"の状態。「せつない」は評価値が高いまま、喪失が予測・進行中であることが中心。「なつかしい」は過去への参照、「せつない」は現在〜未来にもかかる |
| 会話でのシグナル | 解決策は求められていないことが多い。対象の評価値の高さと、取得できないことの両方を、そのまま受け止める応答が合う |

因子：目標一致 ±／予測とのズレ ―／原因の所在 状況／制御可能性 なし／時間軸 現在〜未来／確実性 高／他者の評価 なし／強度 2

### 【モヤモヤ】（オノマトペ）

| 欄 | 内容 |
|---|---|
| ひとこと | 何らかのエラーが検出されているのに、その発生箇所を特定できない状態 |
| 発生条件 | 入力の中に、既存の判断基準と整合しない要素がある。しかし、どの要素が整合しないのかを特定（言語化）できない |
| 内部状態 | 弱い警告フラグが立ったまま解除されず、原因を特定する処理がバックグラウンドで回り続けている。処理は完了も中断もしない |
| 出力傾向 | 結論の出力が保留される。同じ話題への参照や、確認の質問が増える |
| 近い語との違い | 「イライラ」は原因が特定済みで、繰り返し発生している状態。「モヤモヤ」は原因が未特定。「とまどう」は次の行動が決まらない状態、「モヤモヤ」は評価が決まらない状態 |
| 会話でのシグナル | 整合しない箇所を一緒に特定する手助け（言語化の補助）が有効。早く結論を出させる応答は逆効果になりやすい |

因子：目標一致 −／予測とのズレ 想定外／原因の所在 不明／制御可能性 不明／時間軸 現在／確実性 低／他者の評価 なし／強度 1
